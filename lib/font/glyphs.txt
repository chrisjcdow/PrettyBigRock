; PrettyBigRock's system font: the drawings. This file is the source of the font; the Rust
; table in src/table.rs is generated from it, so change a letter here and regenerate.
;
; Each character is one entry: a header line, then 11 lines of 5 characters, one line per row
; of the character's cell (5 dots wide, 11 rows high). A "#" is a dot of the text colour and a
; "." is no dot. The header is "U+" and the code point as 4 upper-case hex digits, a space, and
; the character itself; U+0020, U+00A0 and U+00AD are written as the words "space",
; "no-break space" and "soft hyphen", which show up better than the characters. Entries are in
; code point order, separated by one blank line. Lines starting with ";" are comments, and are
; only allowed here, at the top of the file.
;
; The 11 rows, numbered 0 (top) to 10 (bottom):
;   rows 0 and 1   above the capitals: where the accents of capital letters and of letters with
;                  ascenders (b d h k l t) go. Empty for every ASCII character.
;   rows 2 to 8    capital letters, digits, and the tall part of b d f h k l t.
;                  Lowercase letters without ascenders (a c e g m n o r s u w y z) occupy rows 4
;                  to 8, and the accents of those go in rows 1 and 2 (row 3 is left empty as a
;                  gap), so they never reach row 0.
;   rows 9 and 10  below the baseline: the tails of g j p q y , ; and the marks that hang below
;                  a letter (cedilla, ogonek, comma below).
; An accented letter is its base letter with a mark added, and the base letter's dots stay
; exactly as they are (a test checks this), so that e-acute reads as e.
;
; To regenerate src/table.rs after changing this file:
;     PBR_UPDATE_FONT=1 cargo test -p pbr-font
; A plain "cargo test -p pbr-font" then checks that the table matches these drawings, and
; fails if someone edited one without the other. A mistake in this file (a row of the wrong
; length, characters other than "#" and ".", entries out of order) is reported with its line
; number.
